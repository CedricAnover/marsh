# v0.4.0 — Stable Workflow Kernel

**Status:** In development

v0.4.0 hardens Marsh's provider-independent semantic kernel before remote execution readiness.

## Implemented so far

- canonical semantic ownership and lifecycle contract;
- deterministic, read-only semantic inspection shared by the CLI and kernel;
- explicit capability requirement/negotiation results;
- provider-independent process identity;
- explicit cancellation/timeout evidence;
- postcondition-based recovery primitive;
- provider negative-path conformance coverage;
- cross-process execution-identity verification;
- README and documentation index updates.

## Release scope

The release is intentionally limited to semantic kernel and conformance work. It does **not** introduce remote transport, a distributed control plane, gRPC/Protocol Buffers, a second runtime/scheduler, or a mandatory new runtime dependency.

## Verification gates

Before release:

- focused v0.4.0 tests pass;
- full pytest suite passes;
- lint and package build pass;
- CircleCI Python 3.10/3.11/3.12, lint, build, and integration gates pass;
- GitHub Actions Linux and Windows portability gates pass;
- provider/adapter negative-path conformance is green;
- cross-process and relevant cross-OS evidence is green;
- security/redaction review is complete;
- compatibility and documentation review is complete;
- protected main promotion is approved;
- release tagging is performed only in the required ephemeral Upstash Box;
- the Upstash Box is deleted immediately after release work;
- main and develop are synchronized at the release commit.

## v0.4.1 boundary

Remote execution work may consume these contracts but must not redefine lifecycle, identity, cancellation, ambiguity, artifact, or reconciliation semantics.

# v0.3.9 — UX & Extension Convergence

## Summary

v0.3.9 adds a thin application and extension boundary around the canonical
Marsh workflow/runtime contracts.

## Delivered

- Read-only CLI inspection with deterministic human and JSON output.
- Stable package version reporting through the installed distribution metadata.
- Deterministic extension discovery through the `marsh.extensions` entry-point group.
- Compatibility gating through the `Marsh-Extension-Contract` metadata field.
- Secret-safe diagnostics for credential-like fields and authorization values.
- Cross-version conformance through CircleCI for Python 3.10, 3.11, and 3.12.
- GitHub Actions validation for the repository's Linux, Windows, Docker, and SSH smoke paths.
- CLI, extension, and release documentation.

## Compatibility boundary

The release keeps these concerns distinct:

1. Marsh package version.
2. Extension contract version.
3. Workflow IR version.
4. Extension package version.

Only the extension contract controls activation compatibility in v0.3.9.

## Non-goals

v0.3.9 does not introduce a second workflow engine, new scheduler semantics,
remote execution, or a generalized plugin framework.

## Verification

The release is accepted only when the full CircleCI and GitHub Actions evidence
is green and the final `main` and `develop` refs are synchronized.

## Detailed release notes

# Marsh v0.3.9 — UX & Extension Convergence

v0.3.9 adds a small, dependency-free application boundary around the canonical
workflow/runtime semantics.

## CLI inspection

The marsh CLI is read-only for inspection:

    marsh inspect workflow.json
    marsh inspect workflow.json --json

Inspection validates and plans the workflow but never executes it. Machine-readable
output is deterministic JSON.

## Extension discovery

Optional integrations can advertise entry points in the marsh.extensions group.
Discovery is deterministic and sorted by extension name/value. Extensions must
declare Marsh-Extension-Contract metadata matching the current contract version.

An incompatible extension is rejected before loading. The core package remains
dependency-light when no extension is installed.

## Diagnostics

CLI diagnostics redact credential-like mapping keys and common authorization values.
Applications should treat diagnostics as safe-to-display output, but should still
avoid deliberately passing secrets into workflow metadata.

## Compatibility

v0.3.9 distinguishes the Marsh package version, extension contract version,
workflow IR version, and extension package version. Only the extension contract
controls activation compatibility.

## Scope boundary

v0.3.9 does not add remote execution, a new scheduler, a generalized plugin
framework, or a second workflow semantic model.

# v0.4.4 — Resource Model & Provider Foundation

## Scope

v0.4.4 introduces the minimum resource foundation required for Marsh to model lifecycle-bearing infrastructure capabilities without introducing a second runtime, scheduler, distributed control plane, or mandatory infrastructure dependency.

## Implemented

- `ResourceIdentity` provides stable `kind:name` semantic identity.
- `ResourceState` defines explicit lifecycle and recovery states.
- `Resource` carries identity, lifecycle evidence, and provider-independent metadata.
- `ResourceGraph` provides deterministic identity lookup and dependency relationships.
- `ResourceProvider` is an optional structural provider contract for resource capabilities.
- Local and Docker providers demonstrate machine-resource creation through the same semantic contract.
- `ArtifactStoreResourceAdapter` demonstrates a materially different artifact-store resource domain without introducing a future storage framework.
- Public exports, README, concepts, extension guidance, and release documentation describe the implemented behavior.

## Compatibility

The core package remains dependency-light. Existing `Provider` implementations do not need to implement `ResourceProvider`. Python 3.10–3.12 remains supported.

The existing Workflow, Task, Scheduler, Machine, Process, Result, Policy, Observer, ArtifactStore, and extension boundaries remain intact.

## Verification

Focused resource/provider tests and the CI-equivalent non-Docker baseline suite must pass before release. Docker and SSH integration remain environment-dependent and are verified in the integration environment with the repository's existing CI commands.

Release verification also requires a successful package build, diff check, dependency-boundary check, security review, and tag verification from `main`.

# v0.4.2 — Provider & Adapter Hardening

**Release date:** 2026-10-06

v0.4.2 hardens Marsh's provider and adapter boundaries without changing the canonical Workflow/Task/Execution/Attempt/Process/Result/Artifact model.

## What changed

- Normalized provider capability discovery into explicit supported, unsupported, unavailable, and indeterminate states.
- Added deterministic CapabilityMatch admission evidence and pre-dispatch capability rejection.
- Added heterogeneous Local/Docker conformance and explicit provider-unavailability diagnostics.
- Kept Docker and SSH integrations optional and isolated from core imports.
- Added adapter-owned partial-failure restoration and ambiguity-preservation tests using the existing bounded postcondition recovery primitive.
- Strengthened adapter-boundary tests and updated README/semantic-contract documentation.

## Verification

CircleCI lint/build, Python 3.10/3.11/3.12 baseline tests, Docker integration, SSH integration, provider conformance, and recovery tests passed.

## Scope

No mandatory runtime dependency, second runtime/scheduler, or production distributed transport was introduced.

## Release process

The v0.4.2 tag is created only after final protected-branch synchronization and release-integrity checks. The ephemeral release environment is reserved for the tag operation and deleted immediately afterward.

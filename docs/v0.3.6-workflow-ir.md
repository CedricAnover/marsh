# v0.3.6 Workflow IR

Marsh v0.3.6 establishes the versioned `marsh.workflow/v1` canonical Workflow IR.

The IR is a semantic boundary, not a second runtime. Python authoring, mappings, and future declarative inputs converge on the same versioned document before existing runtime/scheduler execution.

## Contract

```text
Authoring -> Configuration -> Canonical Workflow IR -> JSON -> Reconstruction -> Runtime
```

The document envelope is:

```text
WorkflowDocument
+- schema
|  +- name = marsh.workflow
|  +- version = 1
+- workflow
|  +- id
|  +- tasks[]
|  +- inputs
|  +- outputs
|  +- metadata
+- extensions
```

Executable Python operations are represented as explicit `OperationRef` values:

```json
{"kind":"python_callable","module":"package.tasks","qualname":"build"}
```

Serialized workflow data is never executed as Python source. Resolution imports the named module and traverses the named attribute path. Lambdas, local functions, and `__main__` operations are rejected because they are not portable semantic references.

Canonical JSON uses recursively normalized data, stable task ordering, string object keys, and `allow_nan=False`. Runtime-only values such as sockets, file handles, locks, processes, arbitrary class instances, and raw bytes are rejected by the v1 contract.

The package version and IR schema version are independent. Unknown IR versions fail explicitly.

## Compatibility

The existing `workflow_to_dict()`, `workflow_to_json()`, `workflow_from_dict()`, and `workflow_from_json()` APIs remain available as a compatibility façade. They now operate on the canonical v1 envelope.

The runtime remains responsible for execution. The IR does not introduce a second scheduler or provider model.

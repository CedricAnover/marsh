# v0.3.2 Test Portability Audit

Date: 2026-10-04
Release: v0.3.2
Base branch: develop

## Scope

Make the test suite platform-independent without changing Marsh execution semantics.

## Portability boundary

### Portable unit tests

These tests must not depend on a host shell executable when shell/process behavior is not the subject:

- `tests/core/test_executor.py`
  - callback behavior
  - timeout behavior
  - invalid callback return behavior
  - mocked subprocess lifecycle
- Core/runtime tests that use `sys.executable` for genuine Python subprocess behavior.

### Genuine subprocess tests

A real subprocess is appropriate when process lifecycle/exit/timeout behavior is the behavior under test.

Current examples:

- `tests/core/test_runtime.py` uses `sys.executable` for deterministic Python subprocesses and timeout/cancellation coverage.

Rule: use `sys.executable` rather than a shell convenience command.

### Provider/OS integration tests

These intentionally retain provider-specific or OS-specific behavior and must stay outside the portable Windows unit gate:

- `tests/bash/` — Bash provider/grammar/script behavior.
- `tests/docker/` — Docker provider/integration behavior; commands such as `bash`, `echo`, and `sleep` are exercised inside containers.
- `tests/ssh/` — SSH/provider acceptance and remote shell behavior.
- `tests/core/test_py_command_grammar.py` — explicit command-grammar construction for configured shell commands; this tests command construction, not local Windows execution.

## Issue #90 and sibling findings

`tests/core/test_executor.py` contained unit tests that selected Unix shell commands (`bash`, `echo`, `sleep`) even though the tests were validating executor callback/timeout/result semantics. Those dependencies make the tests host-shell dependent.

The v0.3.2 fix is to mock `subprocess.Popen` for those semantics tests. Production `LocalCommandExecutor` remains unchanged and continues to use `shell=False`.

## Policy

1. Mock process creation when subprocess behavior itself is not the subject.
2. Use `sys.executable` for genuine Python subprocess tests.
3. Do not use `echo`, `bash`, `sh`, `sleep`, or similar commands merely as convenient test fixtures.
4. Keep provider/OS integration tests explicitly separated from portable unit tests.
5. Do not add a subprocess-testing dependency without evidence that the existing stdlib/pytest tooling is insufficient.

## CI boundary

- CircleCI Linux Python 3.10/3.11/3.12: broad compatibility.
- GitHub Actions Windows Python 3.12: native portability gate.
- GitHub Actions Ubuntu + Docker: Docker integration.
- Existing SSH integration: SSH/provider acceptance.

Native Windows is the portability gate. Linux Docker is not a substitute for native Windows.

## Exit evidence

The audit is complete when:
- OS-dependent tests have an explicit classification;
- executor unit tests contain no accidental host-shell dependency;
- genuine subprocess tests use a portable executable;
- CI explicitly separates portable tests from provider/OS integration;
- no production execution semantics were changed for portability.
